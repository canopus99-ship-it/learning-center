# 데이터 보안 설정 (Supabase 권한 정리) - 적용 방법

## 왜 필요한가
현재 대부분의 표 권한이 `{public} ALL true`(누구나 모든 작업 허용)입니다.
웹페이지에 들어 있는 공개 키(anon key)만 있으면 **로그인하지 않은 외부인도**
회원·결제·직원 명단을 조회/수정/삭제할 수 있고, 직원 명단(staff_members)에 스스로를 관리자로 추가할 수도 있습니다.
→ "등록된 활성 직원만" 데이터에 접근하도록 바꿉니다. 코드 배포는 필요 없습니다(SQL만 실행).

## 실행 (Supabase → SQL Editor → New query → 전체 붙여넣고 Run)
수업 시간을 피해서, 실행 직후 아래 '확인'을 바로 해 주세요.

```sql
-- 1) 로그인한 사람이 '등록된 활성 직원'인지 / '관리자'인지 확인하는 함수
create or replace function public.is_active_staff() returns boolean
language sql stable security definer set search_path = public as $$
  select exists (
    select 1 from staff_members s
    where lower(s.email) = lower(coalesce(auth.jwt() ->> 'email', '')) and s.is_active
  );
$$;

create or replace function public.is_admin_staff() returns boolean
language sql stable security definer set search_path = public as $$
  select exists (
    select 1 from staff_members s
    where lower(s.email) = lower(coalesce(auth.jwt() ->> 'email', '')) and s.is_active and s.role = 'admin'
  );
$$;

grant execute on function public.is_active_staff() to authenticated;
grant execute on function public.is_admin_staff() to authenticated;

-- 2) 업무 데이터 표: 기존 '누구나 허용' 규칙을 모두 지우고 '활성 직원만' 규칙으로 교체
do $$
declare t text; p record;
begin
  foreach t in array array[
    'attendance','course_dates','course_levels','course_sessions','courses','enrollments',
    'instructors','lesson_attendance','lesson_closed_days','lesson_fixed_schedules','lesson_schedules',
    'member_memos','members','payments','app_settings','course_level_changes'
  ] loop
    execute format('alter table public.%I enable row level security', t);
    for p in select policyname from pg_policies where schemaname = 'public' and tablename = t loop
      execute format('drop policy %I on public.%I', p.policyname, t);
    end loop;
    execute format(
      'create policy staff_only on public.%I for all to authenticated using (public.is_active_staff()) with check (public.is_active_staff())',
      t
    );
  end loop;
end $$;

-- 3) 직원 명단: 본인 행 조회는 누구나(로그인 확인용), 직원은 전체 조회, 추가·수정·삭제는 관리자만
do $$
declare p record;
begin
  for p in select policyname from pg_policies where schemaname = 'public' and tablename = 'staff_members' loop
    execute format('drop policy %I on public.staff_members', p.policyname);
  end loop;
end $$;
alter table public.staff_members enable row level security;
create policy staff_read on public.staff_members for select to authenticated
  using (lower(email) = lower(coalesce(auth.jwt() ->> 'email', '')) or public.is_active_staff());
create policy admin_write on public.staff_members for all to authenticated
  using (public.is_admin_staff()) with check (public.is_admin_staff());

-- 4) 결과 확인 (모든 표가 staff_only / staff_read / admin_write 로 나오면 정상)
select tablename, policyname, roles, cmd from pg_policies where schemaname = 'public' order by tablename;
```

## 실행 직후 확인
1. 관리자 계정: 홈 → 회원관리, 수납관리, 출석부, 통계, 강사료, 직원관리 화면이 평소처럼 열리고 목록이 보이는지
2. 태블릿 계정(강사): 출석부 열기 → 출석 체크 1번 → 다시 해제
3. 공개 강좌검색 페이지(/courses-search)가 평소처럼 나오는지 (서버 전용 키를 써서 영향 없음)

## 문제가 생기면 (되돌리기 — 일단 '로그인한 사람은 누구나'로 임시 복구)
```sql
do $$
declare t text; p record;
begin
  foreach t in array array[
    'attendance','course_dates','course_levels','course_sessions','courses','enrollments',
    'instructors','lesson_attendance','lesson_closed_days','lesson_fixed_schedules','lesson_schedules',
    'member_memos','members','payments','app_settings','course_level_changes','staff_members'
  ] loop
    for p in select policyname from pg_policies where schemaname = 'public' and tablename = t loop
      execute format('drop policy %I on public.%I', p.policyname, t);
    end loop;
    execute format('create policy temp_all on public.%I for all to authenticated using (true) with check (true)', t);
  end loop;
end $$;
```
되돌린 경우에도 예전보다는 안전합니다(로그인 안 한 외부인은 차단). 화면 캡처를 보내주시면 원인을 찾아 다시 적용합니다.

## 참고
- 태블릿 계정도 '활성 직원'이라 DB 권한은 직원과 같습니다. 화면 접근은 기존처럼 출석부만 가능(미들웨어·권한 체크).
- 영수증 번호 표(receipt_counters)는 4차 SQL에서 직접 접근을 막아 두었고, 번호 발급 함수로만 사용됩니다.
